#   that satisfies both, so it is the floor and the ceiling for now.

# --- ML ---
# scikit-learn is pinned exactly because it is the version that wrote the
# pickles in models/ (confirmed: they carry a 1.3.2 version stamp). On 1.9.1
# the two GradientBoosting models fail with
# ModuleNotFoundError: sklearn.ensemble._gb_losses.
#
# This pin is NOT protecting anything valuable and is free to move once the
# NHANES models land. Those artefacts were trained on the withdrawn dataset
# with rule-derived labels (CLAUDE.md Findings 1 and 5) and are being
# deleted. 1.3.2 is kept only because it works on 3.12 and nothing forces a
# change today.
scikit-learn==1.3.2
# numpy is held below 2.0: scikit-learn 1.3.2 is built against the numpy 1.x
# ABI. Moving numpy without moving scikit-learn will break at import.
numpy==1.26.4
pandas==2.1.4

# --- reporting figures ---
# scripts/build_figures.py only. Pinned to 3.8.x because 3.9+ resolves to
# numpy 2.x, which silently upgrades numpy past the 1.x ABI that
# scikit-learn 1.3.2 is built against; pandas then fails at import with
# "numpy.dtype size changed". Installing matplotlib unpinned breaks this
# environment -- it was tried on 2026-09-21 and did exactly that.
